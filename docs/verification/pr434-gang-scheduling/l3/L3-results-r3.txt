IMPORTANT setup note on the admission negatives
-----------------------------------------------
On the first pass the two admission negatives were ACCEPTED. Root cause: the
cluster's rbgs-validating-webhook-configuration is the 27-day-old v0.8.0 chart
config, which routes ONLY `rolebasedgroups` to the webhook — it predates
PR-434 and has no `coordinatedpolicies` rule. Swapping just the controller
image does not update the VWC, so the API server never called the (present and
running) ValidateCoordinatedPolicyGang handler. This is a SETUP ARTIFACT of the
image-only swap, NOT a product gap: PR-434 ships the wiring in
config/webhook/manifests.yaml (webhook `vcoordinatedpolicy.kb.io`, path
/validate-workloads-x-k8s-io-v1alpha2-coordinatedpolicy, resources
[coordinatedpolicies], operations CREATE/UPDATE), and main.go registers it via
CoordinatedPolicy.SetupWebhookWithManager. To prove the fix live, the PR's
coordinatedpolicies rule was added to the live VWC (reusing the same
service/caBundle); both negatives were then correctly DENIED with the messages
above. The VWC was restored to its original single-webhook state at teardown.

F8  (policy read error swallowed) — not exercisable live without fault
    injection; covered by L1 TestVerifyR3_F8 with an interceptor.
