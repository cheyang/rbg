97:| Older clients read or write the set through v1alpha1 | The conversion webhook stashes `spec.rolloutStrategy` and the v1alpha2-only rollout status fields in `conversion.workloads.x-k8s.io/` annotations on the v1alpha1 view and restores them on write. The round-trip is not lossless: v1alpha1 has no representation for `groupTemplate.labels` and `groupTemplate.annotations`, so such a write drops both maps apart from the compatibility keys restored from the set's own annotations, which changes revision identity and rolls every child. Record in the release notes that rolling sets must be written through v1alpha2. The rendered CRD manifests configure this webhook; a cluster whose CRD lacks it falls back to structural pruning, in which case v1alpha1 writes are not supported. |
