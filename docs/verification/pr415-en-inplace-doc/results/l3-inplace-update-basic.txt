--- what this proves -----------------------------------------------------
1. startTime is UNCHANGED (06:31:12 at both T0 and T1) while restartCount went
   0 -> 1. That is exactly the doc's "Pod AGE not reset, RESTARTS increased".
2. The Pod uid is unchanged, so this is the same API object -- an in-place
   container restart, not a recreate. uid comparison is the reliable test here;
   AGE alone can mislead because `kubectl get` recomputes it from startTime.
3. The node is unchanged, as the doc says for an image-only change.
4. `InPlaceUpdateReady` exists both as a readinessGate and as a condition,
   matching the doc's step 1 ("Controller sets the Pod's InPlaceUpdateReady
   condition to False"). NOTE: the manifest under test did NOT declare
   readinessGates -- the controller injected both gates. The doc does not ask
   the user to add them manually, so this is consistent with the doc; the
   "must be added to template.spec.readinessGates" remark found during review
   was a Go source comment, not a doc claim.
